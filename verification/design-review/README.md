## 一句话结论

**四个工作台现在像"四个插件共用一条 tab 条"，而不是"一个产品"。**
外壳（顶部 tab、保活、统一浅色票）方向是对的，真正缺的是一条**共享的骨架与语法**：同一套导航、同一套标题、同一套空态/控件/密度。补上之后，内容→设计→素材→Logo 能连成一条产线；不补，就永远是四个工具拼在一起。

## P0：先解决这 3 条（不改，后面都是装修）

### 1. 一套导航骨架，而不是四套

现状实测：

| 层 | 现在是什么 | 尺寸 |
|---|---|---|
| 外壳 | 胶囊 tab（创作台 / 内容创作 / 设计 / 设计元素 / Logo），同时右上角又用 11px 文字重复一遍 tab 的内容 | tab 28px 高、13px 字 |
| 内容创作 | 页面内再一条胶囊 nav（灵感/内容/排期/复盘/风格），距一级 tab 只有 14px | 40px 高、276px 宽 |
| 设计 | iframe 内 210px 左侧 rail + 自带品牌头 | rail 210px |
| 设计元素 | iframe 内 300px 左索引（103 条常驻） | 索引 300px |
| Logo | 应用级顶栏（64px）+ 246px 左栏 + 250px 右预览列 | 画布只剩 594px |

问题不是"不好看"，而是**层级不可感知**：用户每切一个 tab 都要重新学"我在第几层"；因为四种框架各管各的，外壳也没法承载跨 tab 的能力（全局新建、最近、搜索）。

建议（推荐 A）：

- **A. 外壳统一左栏 240px**：一级 = 四个工作台，二级 = 当前工作台视图；iframe 页面隐藏自带 rail/标题，只保留内容。
- **B. 保留顶部一级 tab**，但二级统一成"贴内容区的下划线 nav"，不再用胶囊；iframe 同样隐藏自带导航。

视觉上做区分：一级用中性灰小块、无边框；二级用下划线或左侧竖线，**不要都用胶囊**（现在两排看起来是同级）。

### 2. 命名与信息架构

- 「设计」vs「设计元素」：都是设计。设计元素本质是**素材库**（组件、场景、背景场），是"做设计"的零件，不是并列工作台。
- 「Logo」是单个资产的编辑器，更像设计工作台里的一个工具，而不是一级 tab。
- 页面标题今天四套：`内容` / `用一套设计做所有内容` / `设计元素` / `像素 Logo 实验室`；Logo 还有第三套名字在右上（`像素 / 矢量 Logo 编辑器`）。

建议：两级命名收口。

- 一级：**内容 / 设计 / 素材 / Logo**（或 内容 / 设计 / Logo，把素材收进设计的「素材」页）。
- 页面标题统一为「tab 名 + 一句副标题」，iframe 里重复的大标题、品牌头去掉。
- 右上角的 11px 说明文字删掉（改 tooltip 或页面副标题），它和二级 nav 信息完全重复。

### 3. 助手默认收起，把宽度还给主区

- 助手 dock 默认展开、常驻 336px：内容创作主区只剩 824px，看板 4 列被压到约 200px/列。
- 阅读/编辑是主任务，对话是辅助；默认展开挡住的是高频区域。

建议：默认收成右侧 48px 竖条（图标 + 最近一条建议气泡），需要时展开并记住宽度；当窗口 <1200px 时自动收起。

## P1：P0 之后立刻见效

### 4. 空态要有主动作

- 设计「概览」：作品 0 / 专栏 0 / 语气档案未建，页面下半部是大片空白。
- 「我的作品」空态：一个虚线大框 + 一段说明，没有"做第一份"的按钮。
- 内容「复盘」：示例数据下"每日播放"图表只有坐标轴，没有"暂无数据"提示，看起来像 bug。

建议统一空态模板：**一句解释 + 主按钮（开始做第一份 / 用示例数据试试）+ 2–3 个模板入口**。

### 5. 组件库的浏览效率

- 两列约 410px 大卡、单卡 380px 高，同屏只看到 4 个；103 个组件要滚 26 屏。
- 左索引 300px 常驻 103 条英文 API 名（AmberHalftone、BallStudy…），内容创作者读不懂。

建议：3–4 列（卡 300–350px），悬停出"查看 / 复制"；列表模式可选；筛选项收成一行可折叠 chips；左侧改为"搜索 + 分类"而不是全量列表；组件名加中文副标题（AmberHalftone → 琥珀半调），英文名降为小字 API 名。

### 6. 数据页的层次

- 内容「复盘」：渐变 hero + 统计 + 卡片，视觉重心落在渐变上，示例数据标签很小。
- 内容「排期」：日历 + 右列待排 16 条，没有分组/优先级，列表很长。

建议：hero 降饱和、统计数字升一级、示例数据给明显 pill；待排期按「今天 / 本周 / 未定」分组并支持拖入日历。

### 7. 一套控件规范，不是一套颜色

选中态现在有四种：黑底胶囊（内容）、黑底方块（设计 rail）、浅绿底（组件库列表）、segment（Logo 预设）。

建议一张控件表：

- 选中 = 2px 内描边 + 浅底（不要纯黑反白）；
- 主按钮墨黑实心、次按钮 1px 描边、危险红字；
- 高度 28 / 32 / 36 三档，圆角 8，图标 16px 线性；
- 内容区的"作品"统一装进浅色容器（12px 圆角 + 1px 描边 + 内阴影），不要让 Logo 画布、组件黑底预览直接贴在浅外壳上。

### 8. 移动端

430px 实测：tab 可点高度 28px（<44px 拇指友好线）；设计页 rail 退化成竖排文字；组件库左索引占满一屏才轮到网格。

建议：移动端 tab 横向滚动 + 短标签（内容 / 设计 / 素材 / Logo）；二级导航变 segmented 或下拉；双栏页面 <720px 改为"列表 → 详情"；组件库移动端默认网格、筛选进抽屉。

## P2：质感项

9. 顶栏说明文字 → tooltip / 页面副标题；返回对话放左侧或 ⌘[；副标题 ≥12px、对比度 ≥4.5。
10. iframe 首次加载 1–2s 白屏：加骨架屏（外壳常驻，内容区 shimmer）。
11. Logo 页三个"保存"概念（保存版本 / 已同步 / 恢复本地快照）需要 tooltip；宠物与助手浮层避让可交互区域。
12. 跨 tab 联动：内容卡的"封面/配图"标出来自哪个设计作品；设计作品能"用于某条内容"。
13. 全局「＋新建」（灵感 / PPT / 卡片 / Logo），把四个工具串成一条产线。
14. a11y：tab 支持 ←/→、aria-controls；icon-only 按钮补 aria-label；focus ring 统一 2px。

## 实施建议（如果要动手）

1. **第一步（低风险、1 天内）**：助手默认收起 + 空态模板 + 控件规范（选中态/按钮/容器）+ 删掉右上说明文字。
2. **第二步（骨架改造）**：外壳左栏导航 + iframe 隐藏自带 rail/标题 + 标题体系收口；用开关灰度（`?layout=classic`）便于回退。
3. **第三步**：组件库密度与中文名、复盘/排期信息层次、移动端。

每一步都用 `verification/verify-ui.mjs` 增补断言，保持在真实 GUI 里截图验收。
